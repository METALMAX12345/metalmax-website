# METALMAX — сайт

React + Vite + Tailwind CSS 4. Тёмная индустриальная тема с красными акцентами.
Три языка: украинский (по умолчанию), русский, английский.

## Что есть на сайте

- **Главная** (`/`) — hero, услуги, оборудование, портфолио, о компании, отзывы, контакты+FAQ, футер.
- **Отдельные страницы** — `/services`, `/equipment`, `/portfolio`, `/about`, `/contacts`.
- **Админ-панель** — `/admin`. Позволяет без кода менять: подзаголовок hero, текст и статистику
  "О компании", контакты, услуги/оборудование/портфолио (фото, описания, цены),
  отзывы, FAQ.

## Два режима работы

### 1. Локальный демо-режим (по умолчанию, без настройки)

Если не подключать Supabase — всё работает как раньше: контент хранится в `localStorage`
браузера. Пароль в админку: `metalmax`. Изменения видны **только на том устройстве/браузере**,
где их внесли. Хорошо для того, чтобы посмотреть, как всё устроено, но не для реального сайта
с несколькими посетителями.

### 2. Подключённый Supabase (рекомендуется для реального запуска)

Когда переменные окружения заданы (см. ниже), сайт переключается на настоящий бэкенд:

- Весь контент хранится в базе Postgres (таблица `site_content`), а не в браузере —
  **все посетители видят одни и те же изменения**.
- Правки в админке применяются на сайте у всех открытых вкладок **в реальном времени**
  (через Supabase Realtime), без перезагрузки страницы.
- Фото загружаются в Supabase Storage (публичный бакет `media`) и получают обычную
  публичную ссылку — а не превращаются в тяжёлый base64 внутри JSON.
- Вход в админку — через Supabase Auth (email + пароль), а не захардкоженный пароль.
  Только авторизованный пользователь может менять контент — это заложено в политики
  безопасности (RLS) на уровне базы, а не только в интерфейсе.
- Если Supabase временно недоступен — сайт не падает: последняя загруженная версия
  контента остаётся в `localStorage` как кэш.

## Как подключить Supabase — пошагово

1. Зарегистрируйтесь на **supabase.com** и создайте новый проект (бесплатного тарифа
   достаточно). Дождитесь, пока проект поднимется (обычно 1–2 минуты).

2. В Supabase Dashboard откройте **SQL Editor → New query**, вставьте туда содержимое
   файла `supabase/schema.sql` из этого проекта и нажмите **Run**. Это создаст:
   - таблицу `site_content` с политиками доступа (читать может любой посетитель,
     редактировать — только авторизованный админ);
   - публичный бакет `media` для фото с такими же политиками.

3. Создайте себе учётку администратора: **Authentication → Users → Add user**,
   укажите email и пароль. Именно этими данными вы будете логиниться на `/admin`.

4. Возьмите ключи проекта: **Project Settings → API**. Скопируйте:
   - `Project URL`
   - `anon public` ключ

5. В корне проекта скопируйте `.env.example` в `.env` и вставьте туда эти значения:
   ```
   VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

6. Пересоберите/перезапустите сайт (`npm run dev` или `npm run build`). В шапке
   админки появится индикатор "Синхронізовано" вместо "Локальний режим" — значит
   всё подключилось.

7. При деплое (Cloudflare Pages / Vercel / Netlify) добавьте эти же две переменные
   окружения в настройках проекта хостинга — иначе на проде сайт снова уйдёт
   в локальный режим.

**Важно:** `.env` с реальными ключами не должен попадать в git — он уже добавлен
в `.gitignore`.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # прод-сборка в dist/
```

## Деплой (Cloudflare Pages / Vercel)

- Залейте папку `site` (без `node_modules`) в репозиторий на GitHub.
- Подключите репозиторий в Cloudflare Pages или Vercel.
- Build command: `npm run build` — Output directory: `dist`.
- Добавьте переменные окружения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`
  (если используете Supabase).

## Структура

```
src/
  components/        общие UI-компоненты (Header, Hero, Services, Equipment, Portfolio,
                      About, Testimonials, FAQ, Contacts, Footer, PageBanner, ...)
  components/admin/  ListEditor — добавление/удаление/сортировка + загрузка фото
  data/cms.jsx        хранилище контента: localStorage + синхронизация с Supabase
  lib/supabaseClient.js  подключение к Supabase (не активно, если .env пустой)
  lib/useAdminAuth.js     хук авторизации (Supabase Auth или демо-пароль)
  i18n/               языковой контекст + словари uk.json / ru.json / en.json
  pages/              Home.jsx, ServicesPage.jsx, EquipmentPage.jsx, PortfolioPage.jsx,
                      AboutPage.jsx, ContactsPage.jsx, admin/AdminLogin.jsx, admin/AdminDashboard.jsx
supabase/
  schema.sql          SQL для настройки таблицы, RLS-политик и бакета для фото
.env.example          шаблон переменных окружения для Supabase
```

## Известные ограничения

- Русская и английская версии текста (`ru.json`, `en.json`) остаются статичными
  переводами и не редактируются через админку — редактируется только украинская
  версия (она же основная/дефолтная).
- Фото оборудования/портфолио на данный момент — авторская SVG/CSS-графика
  (индустриальный стиль, соответствующий референсам), так как у меня нет доступа
  к реальным фотографиям вашего производства. Как только они появятся — загружайте
  через админку, замена происходит без правок кода.
